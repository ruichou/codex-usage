# Codex 用量悬浮窗设计

## 目标

制作一个 Windows 桌面悬浮窗，显示 Codex 当前用量周期的剩余额度，包括剩余百分比和重置时间。窗口应当一眼可读；当本地无法读取用量时，绝不虚构数字。

## 范围

### 首版包含

- 使用 Python + Tkinter + Python 标准库实现。
- 紧凑的深色悬浮窗，支持置顶和拖动。
- 显示剩余百分比、进度条、重置时间/倒计时、最后更新时间。
- 每 30 秒自动刷新。
- 右键菜单支持立即刷新和退出。
- 明确的“暂时无法获取”错误状态。
- 独立的用量读取模块，便于未来适配 Codex 本地数据格式变化。
- 覆盖解析、格式化和错误处理的单元测试。

### 首版不包含

- 登录、API Key 管理或修改 Codex 凭据。
- 修改 Codex 用量限制。
- 云同步、遥测或网络请求，除非发现的本地数据源明确要求网络访问。
- 安装程序、系统托盘图标和开机启动注册。这些功能放到稳定版本之后。

## 技术方案

使用 Python 3 和 Tkinter，并拆分为三个职责明确的部分：

1. `usage_reader`：发现并读取本机可用的 Codex 用量数据源，返回统一格式的 `UsageSnapshot`，或返回明确的“不可用”结果。
2. `formatting`：把统一数据转换为显示文本、百分比、倒计时和状态颜色。该模块保持纯函数形式，便于测试。
3. `app`：负责 Tkinter 窗口、刷新定时器、拖动、右键菜单和界面渲染，不包含特定数据源的解析逻辑。

读取模块首先检查本机可用的 Codex 状态数据。如果找不到支持的数据源，界面显示无法检测到用量数据。程序不得根据 token 数量估算额度，也不得把过期数字伪装成当前数字；如果使用上一次成功数据，必须明确标记为“数据可能已过期”。

## 视觉系统

- 背景：深炭黑色，避免使用纯黑；卡片表面略亮。
- 主色：电光蓝，用于正常用量进度。
- 警告色：低额度使用琥珀色；错误或额度耗尽才使用红色。
- 字体：主要数值使用易读的系统无衬线字体，标签和时间使用紧凑的等宽字体。
- 布局：窗口宽约 300–340 像素，外边距 16 像素，细边框，14 像素圆角；百分比、进度条和元信息之间留出清晰间距。
- 动效：不做持续动画；如需反馈，只使用很短的刷新过渡，并保持更新即时完成。
- 可访问性：文字保持高对比度；不能只靠颜色表达百分比；右键操作可用键盘触发；尽可能提供清晰焦点样式。

## 窗口行为

- 启动时出现在主屏幕右下角，避免遮挡任务栏。
- 始终显示在其他窗口上方。
- 拖动卡片任意区域即可移动窗口。
- 右键菜单包含“立即刷新”和“退出”。
- 关闭窗口时正常退出。
- 刷新读取不能阻塞界面线程；读取任务放在后台线程中，再通过 Tkinter 事件队列更新界面。

## 数据模型

统一后的快照包含：

- `remaining_percent`：0 到 100 的剩余百分比。
- `reset_at`：额度重置时间；如有，必须包含时区信息。
- `source_timestamp`：数据源报告的读取/生成时间；如有，必须包含时区信息。
- `status`：`ok`、`low`、`exhausted` 或 `unavailable`。
- `message`：不可用或错误状态下的可读说明，可选。

解析器负责把百分比限制在 0–100，拒绝缺失必填字段，并保留重置时间的时区信息。倒计时按照本机时区显示。

## 错误处理

- 缺少或不支持的数据源返回 `unavailable`，不能显示伪造的 `0%`。
- 数据格式错误时在窗口中提示，并在开发阶段写入本地日志或标准错误输出。
- 刷新失败时，只有在明确标记为过期的前提下才能保留上一次成功数据，否则显示不可用。
- 后台读取异常必须在应用边界处捕获，确保悬浮窗仍然响应。

## 验证方式

- 单元测试覆盖：有效快照、百分比边界、缺少字段、重置倒计时格式化和数据源不可用。
- 在有图形环境时，用短生命周期进程启动并关闭 Tkinter 根窗口，验证无异常。
- 手动检查：窗口位置、拖动、置顶、右键菜单、自动刷新、手动刷新和不可用状态。
- 声明完成前，运行完整测试、语法/构建检查，并检查最终 Git diff。

## 验收标准

- Windows + Python 3 环境可启动，且不依赖第三方 Python 包。
- 主窗口是紧凑、可拖动、始终置顶的悬浮窗。
- 检测到支持的用量数据源时，显示当前周期剩余百分比和重置信息。
- 数据源缺失或无效时，清楚显示用量不可用，同时窗口仍可操作。
- 每 30 秒自动刷新，也可以手动刷新。
- 测试通过，且不存在阻塞界面线程或未处理的读取异常。
